## 1. 冒泡排序 (Bubble Sort)

### 核心思想

重复遍历数组，依次比较相邻的两个元素，如果顺序错误（前 > 后）就交换它们。每一轮遍历会把当前未排序部分的最大值"冒泡"到末尾。

### 算法步骤

```
1. 从数组开头开始，依次比较相邻元素 arr[j] 和 arr[j+1]
2. 如果 arr[j] > arr[j+1]，交换两者
3. 每完成一轮，最大的元素被放到正确的位置（数组末尾）
4. 重复 n-1 轮，直到数组完全有序
```

### 动画演示

```
初始: [5, 3, 8, 1]

第1轮: [3, 5, 1, 8]  ← 8 冒泡到末尾
第2轮: [3, 1, 5, 8]  ← 5 冒泡到末尾
第3轮: [1, 3, 5, 8]  ← 3 冒泡到末尾
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | **O(n)** | 数组已有序，优化版一轮无交换即退出 |
| 平均 | O(n²) | 需要 n(n-1)/2 次比较 |
| 最坏 | O(n²) | 完全逆序，每次都要交换 |

- **空间复杂度**：O(1)，原地排序
- **稳定性**：✅ 稳定（相邻相等元素不交换）

### 优化策略

添加 `swapped` 标记：如果某一轮没有发生任何交换，说明数组已经有序，可以提前结束循环。

### 适用场景

- 数据量小（n ≤ 100）
- 教学目的，理解排序的基本思想
- 数据基本有序时表现较好（优化版）

### 不适用场景

- 大数据量：O(n²) 太慢
- 对性能有要求的场景

## 2. 选择排序 (Selection Sort)

### 核心思想

将数组分为"已排序区"和"未排序区"。每一轮从未排序区中选出最小的元素，放到已排序区的末尾。

### 算法步骤

```
1. 从 i=0 开始，在第 i 到 n-1 的元素中找到最小值的下标 minIdx
2. 将 arr[minIdx] 与 arr[i] 交换
3. i 右移一位，重复直到 i=n-1
```

### 动画演示

```
初始: [5, 3, 8, 1]

第1轮: 选最小 1 → [1, 3, 8, 5]
第2轮: 选最小 3 → [1, 3, 8, 5]
第3轮: 选最小 5 → [1, 3, 5, 8]
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(n²) | 无论数据如何，每轮都要扫描剩余全部元素 |
| 平均 | O(n²) | 比较次数恒为 n(n-1)/2 |
| 最坏 | O(n²) | 同上 |

- **空间复杂度**：O(1)，原地排序
- **稳定性**：❌ 不稳定（交换可能破坏相等元素的相对顺序）

> 例如 `[5, 8, 5, 2]`：第一轮选最小 2 与第一个 5 交换，两个 5 的相对顺序改变。

### 适用场景

- 数据量很小（n ≤ 50）
- 数据移动成本很高（每轮最多交换一次）
- 内存写入次数受限的场景（如 Flash 存储）

### 不适用场景

- 大数据量
- 需要稳定排序的场景

## 3. 插入排序 (Insertion Sort)

### 核心思想

类似于打扑克牌时整理手牌。每次从未排序区取出第一个元素，在已排序区中从后往前扫描，找到合适的位置插入。

### 算法步骤

```
1. 从第 2 个元素（i=1）开始，认为第 1 个元素已经有序
2. 取出当前元素 key = arr[i]
3. 在已排序区 [0, i-1] 中从后往前找：如果 arr[j] > key，就把 arr[j] 后移一位
4. 找到合适位置后，把 key 放进去
```

### 动画演示

```
初始: [5, 3, 8, 1]

插入 3: [3, 5, 8, 1]  ← 3 插入到 5 前面
插入 8: [3, 5, 8, 1]  ← 8 已在正确位置
插入 1: [1, 3, 5, 8]  ← 1 插入到最前面
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | **O(n)** | 数组已有序，每轮只比较一次 |
| 平均 | O(n²) | 平均需要移动一半的元素 |
| 最坏 | O(n²) | 完全逆序，每次都要移到最前面 |

- **空间复杂度**：O(1)，原地排序
- **稳定性**：✅ 稳定（后移时用 `>` 而非 `>=`，相等元素不后移）

### 适用场景

- 数据量小（n ≤ 50），此时比快排、归并更快
- **数据基本有序**（如对已排序数据插入少量新元素）
- 作为高级排序算法的小规模子问题优化（如 JDK TimSort 中）
- 在线排序（数据逐个到达，实时插入）

### 不适用场景

- 大规模随机数据

## 4. 希尔排序 (Shell Sort)

### 核心思想

插入排序的改进版，也称为"缩小增量排序"。先对间隔较大的子序列进行排序，让数组逐步变得"基本有序"，最后再用间隔为 1 的普通插入排序完成。

### 算法步骤

```
1. 选择一个增量序列（gap），通常从 n/2 开始，每次减半直到 1
2. 对每个 gap，将数组分成 gap 个子序列，对每个子序列做插入排序
3. 缩小 gap，重复步骤 2
4. 当 gap = 1 时，就是普通插入排序，但此时数组已经基本有序
```

### 动画演示

```
初始: [9, 8, 7, 6, 5, 4, 3, 2, 1]

gap=4: 分 4 组 → [1, 4, 3, 2, 5, 8, 7, 6, 9]
gap=2: 分 2 组 → [1, 2, 3, 4, 5, 6, 7, 8, 9]
gap=1: 普通插入 → [1, 2, 3, 4, 5, 6, 7, 8, 9]
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(n log n) | 取决于增量序列 |
| 平均 | ~O(n^(3/2)) | 使用 n/2 递减序列 |
| 最坏 | O(n²) | 使用 n/2 递减序列时 |

- **空间复杂度**：O(1)，原地排序
- **稳定性**：❌ 不稳定（分组排序时相同元素可能被分到不同组）

### 增量序列选择

| 增量序列 | 公式 | 最坏时间复杂度 |
|----------|------|---------------|
| Shell 原始 | gap = n/2, n/4, ..., 1 | O(n²) |
| Hibbard | 1, 3, 7, 15, ..., 2^k - 1 | O(n^(3/2)) |
| Sedgewick | 1, 5, 19, 41, 109, ... | O(n^(4/3)) |

### 适用场景

- 中等规模数据（n ≤ 5000）
- 嵌入式系统等内存受限环境（原地排序）
- 不需要稳定排序的场景

### 不适用场景

- 需要稳定排序
- 大规模数据（不如快排/归并）

## 5. 归并排序 (Merge Sort)

### 核心思想

采用经典的分治（Divide and Conquer）策略。将大数组递归拆分成两个小数组，分别排序，然后将两个有序小数组合并成一个有序大数组。

### 算法步骤

```
1. 分解（Divide）：将数组从中间分成左右两半
2. 解决（Conquer）：递归地对左右两半分别进行归并排序
3. 合并（Combine）：将两个有序子数组合并成一个有序数组
```

### 动画演示

```
                  [38, 27, 43, 3, 9, 82, 10]
                     /                    \
              [38, 27, 43, 3]        [9, 82, 10]
               /          \           /        \
          [38, 27]      [43, 3]    [9, 82]    [10]
          /     \       /     \    /    \       |
       [38]    [27]   [43]   [3] [9]   [82]  [10]
          \     /       \     /    \    /       |
          [27, 38]      [3, 43]    [9, 82]    [10]
               \          /           \        /
              [3, 27, 38, 43]        [9, 10, 82]
                     \                    /
                  [3, 9, 10, 27, 38, 43, 82]
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(n log n) | 始终如此 |
| 平均 | O(n log n) | 始终如此 |
| 最坏 | O(n log n) | 始终如此 |

- **空间复杂度**：O(n)，需要临时数组存储合并结果
- **稳定性**：✅ 稳定（合并时相等元素优先取左边的）

### 优化策略

1. **小数组用插入排序**：当子数组长度 ≤ 某个阈值（如 15），改用插入排序
2. **合并前检查**：如果 `arr[mid] ≤ arr[mid+1]`，说明已经有序，无需合并

### 适用场景

- 需要稳定排序且数据量大
- **外部排序**（数据在磁盘上无法一次性读入内存）——归并排序是外部排序的基础
- 链表排序（归并排序在链表上不需要额外空间）
- 对最坏情况有要求的场景（始终 O(n log n)）

### 不适用场景

- 内存受限且需要原地排序（归并需要 O(n) 额外空间）
- 小数据量（插入排序更快）

## 6. 快速排序 (Quick Sort)

### 核心思想

分治策略。每次选择一个"基准元素"（pivot），将数组分为两部分：左边所有元素 ≤ pivot，右边所有元素 ≥ pivot，然后递归地对左右两部分进行同样的操作。

### 算法步骤

```
1. 选择一个基准元素 pivot（通常选最右边的元素）
2. 分区（Partition）：重排数组，使得 pivot 左边都 ≤ pivot，右边都 > pivot
3. 递归地对左子数组和右子数组进行快速排序
```

### 动画演示

```
初始: [10, 7, 8, 9, 1, 5]  pivot=5

分区:  [1, 5, 8, 9, 10, 7]  pivot=5 归位到 index=1
       /              \
    [1]              [8, 9, 10, 7]  pivot=7
     |               /          \
    [1]          [7, 9, 10, 8]    []
                 /          \
              []         [9, 10, 8]  pivot=8
                         /        \
                      [8, 10, 9]   []
                      /       \
                   []      [10, 9]  pivot=9
                           /     \
                         [9, 10]  []
                          |
                         [9, 10]

结果: [1, 5, 7, 8, 9, 10]
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(n log n) | 每次 pivot 都正好在中间（均匀分割） |
| 平均 | O(n log n) | 实际场景中通常如此 |
| 最坏 | **O(n²)** | 每次 pivot 都是极值（已有序或逆序数组） |

- **空间复杂度**：O(log n)（递归调用栈深度），最坏 O(n)
- **稳定性**：❌ 不稳定（分区时交换会打乱顺序）

### 优化策略

1. **随机选 pivot**：避免最坏情况（已有序数组退化为 O(n²)）
2. **三数取中法**：取左、中、右三个元素的中位数作为 pivot
3. **三路快排**：处理大量重复元素时，分成 < pivot、= pivot、> pivot 三部分
4. **小数组用插入排序**：子数组长度 ≤ 阈值时改用插入排序
5. **尾递归优化**：优先处理较短的一侧，减少递归深度

### 适用场景

- **通用排序的首选**：实际运行速度通常是最快的 O(n log n) 算法
- 大数据量排序
- 内存允许递归调用栈
- 不需要稳定排序

### 不适用场景

- 需要稳定排序
- 数据已基本有序且未做 pivot 优化（退化为 O(n²)）
- 递归深度受限的嵌入式环境

## 7. 堆排序 (Heap Sort)

### 核心思想

利用"堆"（Heap）这种数据结构进行排序。大顶堆中每个节点的值都大于等于其子节点，堆顶就是最大值。通过反复建堆→取堆顶→调整堆的方式完成排序。

### 算法步骤

```
1. 建堆（Build Heap）：将数组原地构建成一个大顶堆
2. 排序：依次将堆顶（最大值）与堆末尾元素交换，然后缩小堆的范围，重新调整堆
3. 重复步骤 2，直到堆的大小为 1
```

### 大顶堆示意图

```
数组: [9, 6, 8, 5, 3, 4, 2, 1]
堆结构:
           9
         /   \
        6     8
       / \   / \
      5   3 4   2
     /
    1

堆顶 9 是最大值，交换到末尾，调整为：
           8
         /   \
        6     4
       / \   / \
      5   3 1   2
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(n log n) | 始终如此 |
| 平均 | O(n log n) | 始终如此 |
| 最坏 | O(n log n) | 始终如此 |

- **空间复杂度**：O(1)，原地排序
- **稳定性**：❌ 不稳定（堆调整时交换会打乱顺序）

### 建堆的复杂度是 O(n) 而非 O(n log n)？

虽然每个节点都可能触发 heapify（O(log n)），但大部分节点在树的底层，heapify 的深度很浅。数学上可以证明建堆的总复杂度是 O(n)。

### 适用场景

- 内存受限，需要原地排序且复杂度稳定
- 只需要前 K 大/小的元素（Top K 问题，不需要完整排序）
- 优先级队列的底层实现（Java `PriorityQueue`）
- 实时系统中需要保证最坏情况性能

### 不适用场景

- 需要稳定排序
- 追求极致速度（通常比快排慢 2-3 倍，因为跳转访问不友好于 CPU 缓存）

## 8. 计数排序 (Counting Sort)

### 核心思想

**非比较排序**。统计每个元素出现的次数，然后根据元素的值直接计算出它在有序数组中的位置。核心是"以空间换时间"。

### 算法步骤

```
1. 找出数组中的最大值和最小值，确定计数范围
2. 创建一个计数数组 count，count[i] 表示元素 i+min 出现的次数
3. 遍历原数组，统计每个元素出现次数
4. 对计数数组做前缀和，此时 count[i] 表示 ≤ i+min 的元素个数
5. 反向遍历原数组，根据计数数组确定每个元素的位置（保证稳定性）
```

### 动画演示

```
原数组:  [4, 2, 2, 8, 3, 3, 1]
计数:    1→1, 2→2, 3→2, 4→1, 8→1
前缀和:  1→1, 2→3, 3→5, 4→6, 8→7
反向填充: [1, 2, 2, 3, 3, 4, 8]
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(n + k) | k 是数据范围 |
| 平均 | O(n + k) | |
| 最坏 | O(n + k) | 当 k 很大时效率降低 |

- **空间复杂度**：O(n + k)
- **稳定性**：✅ 稳定（反向遍历保证）

### 适用场景

- **数据范围 k 远小于数据量 n**（如成绩 0-100、年龄 0-150）
- 整数排序且范围已知
- 需要稳定排序且数据范围小

### 不适用场景

- 数据范围 k 很大（如 0 ~ 10^9），计数数组会太大
- 非整数数据（需转换为整数）
- 数据稀疏分布

### 典型应用

- 考试成绩排名（0-100 分）
- 年龄统计排序
- 高考分数段的考生统计

## 9. 桶排序 (Bucket Sort)

### 核心思想

将数据分散到多个有序的"桶"中，每个桶内部使用其他排序算法（或递归使用桶排序），最后按顺序把各个桶的数据合并起来。

### 算法步骤

```
1. 确定桶的数量，创建桶列表
2. 遍历原数组，根据映射函数将每个元素放入对应的桶中
3. 对每个非空桶内部进行排序
4. 按桶的顺序，依次取出所有元素，放回原数组
```

### 动画演示

```
原数组: [0.78, 0.17, 0.39, 0.26, 0.72, 0.94, 0.21, 0.12, 0.23, 0.68]

桶 0 [0.1, 0.2): [0.17, 0.12]
桶 1 [0.2, 0.3): [0.26, 0.21, 0.23]
桶 2 [0.3, 0.4): [0.39]
桶 3 [0.4, 0.5): []
桶 4 [0.5, 0.6): []
桶 5 [0.6, 0.7): [0.68]
桶 6 [0.7, 0.8): [0.78, 0.72]
桶 7 [0.8, 0.9): []
桶 8 [0.9, 1.0): [0.94]

桶内排序后合并: [0.12, 0.17, 0.21, 0.23, 0.26, 0.39, 0.68, 0.72, 0.78, 0.94]
```

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(n + k) | 数据均匀分布，每个桶元素很少 |
| 平均 | O(n + k) | 取决于桶内排序算法 |
| 最坏 | **O(n²)** | 所有元素落入同一个桶 |

- **空间复杂度**：O(n + k)
- **稳定性**：✅ 稳定（取决于桶内排序是否稳定）

### 适用场景

- 数据均匀分布
- 浮点数排序
- 外部排序（每个桶可以单独写入磁盘再合并）
- MapReduce 框架借鉴了桶排序思想

### 不适用场景

- 数据分布极不均匀
- 数据范围未知

## 10. 基数排序 (Radix Sort)

### 核心思想

按照数字的每一位进行排序。从最低位（LSD）开始，依次对每一位使用稳定排序（通常用计数排序），直到最高位排序完成。

### 算法步骤

```
1. 找出数组中的最大值，确定最大位数
2. 从个位开始，对每一位使用计数排序
3. 逐位处理：个位 → 十位 → 百位 → ... → 最高位
```

### 动画演示

```
原数组: [170, 45, 75, 90, 802, 24, 2, 66]

按个位排: [170, 90, 802, 2, 24, 45, 75, 66]
按十位排: [802, 2, 24, 45, 66, 170, 75, 90]
按百位排: [2, 24, 45, 66, 75, 90, 170, 802]
```

### 为什么从低位开始？

从低位到高位（LSD）排序，高位排序时值相同的元素会保持低位已经排好的顺序。因为每一轮都使用稳定排序，所以高位排序不会破坏低位的排序结果。

### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | O(d × (n + k)) | d=最大位数，k=基数(10) |
| 平均 | O(d × (n + k)) | |
| 最坏 | O(d × (n + k)) | |

- **空间复杂度**：O(n + k)
- **稳定性**：✅ 稳定（每一轮都使用稳定排序）

### 适用场景

- 整数排序，数字位数 d 较小
- 字符串排序（如单词排序）
- 固定长度的数据（如身份证号、电话号码、日期）
- 数据范围很大但位数不多的场景（计数排序的替代方案）

### 不适用场景

- 浮点数（需要特殊处理）
- 位数非常大（如 100 位的大整数）
- 数据量很小（不如简单的比较排序）

## 如何选择合适的排序算法

### 决策流程图

```
                         需要排序？
                            |
                      ┌─────┴─────┐
                      |            |
                  数据量小      数据量大
                  (n ≤ 50)     (n > 50)
                      |            |
              ┌───────┴───────┐    |
              |               |    |
           需要稳定        不需要    需要稳定吗？
              |            稳定      |
         插入排序              |   ┌──┴──┐
              |          选择排序  |      |
              |               |  是     否
              └───────────────┘   |      |
                                  |   内存够吗？
                          归并排序   ┌──┴──┐
                                  |      |
                                 是     否
                              需要的    |
                              是O(n)   快排
                              额外空间  (通用首选)
```

### 速查表

| 场景 | 推荐算法 | 原因 |
|------|---------|------|
| 通用排序 | **快速排序** | 实际速度最快，常数因子小 |
| 需要稳定排序 | **归并排序** 或 **TimSort** | 稳定且 O(n log n)，TimSort 在部分有序时更快 |
| 内存极度受限 | **堆排序** | 原地排序，O(1) 额外空间，且稳定 O(n log n) |
| 数据基本有序 | **插入排序** | 接近 O(n)，简单高效 |
| 数据范围小（整数） | **计数排序** | O(n + k)，线性时间 |
| 数据均匀分布 | **桶排序** | 平均 O(n + k) |
| 位数少的整数 | **基数排序** | O(d × n)，线性时间 |
| 外部排序（磁盘） | **归并排序** | 天然支持分块合并 |
| 链表排序 | **归并排序** | 链表上不需要额外空间 |
| 求 Top K | **堆排序**（部分排序） | 不需要完整排序，O(n log k) |
| 小数组（n ≤ 50） | **插入排序** | 常数因子最小 |
| 嵌入式系统 | **希尔排序** 或 **堆排序** | 原地排序，内存友好 |

### 经验法则

1. **无特殊要求就用快排**：标准库的默认排序（C `qsort`、C++ `std::sort`、Java `Arrays.sort` 对基本类型）
2. **Java 对象排序用 TimSort**：`Arrays.sort(Object[])` 和 `Collections.sort()` 使用 TimSort（归并+插入的混合算法）
3. **需要稳定就用归并**：但需接受 O(n) 额外空间
4. **数据有特殊分布就用非比较排序**：计数、桶、基数排序在特定场景下可达 O(n)
5. **实际使用中直接调标准库**：`Arrays.sort()` 或 `Collections.sort()`，它们经过了高度优化
